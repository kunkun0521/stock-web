# 量化策略研究与回测（/quant）

左侧 / 右侧 / 混合共 5 个内置策略，支持回测、事件研究与每日选股；三者共用同一份策略代码，
保证「回测验证的就是实际选股的」。仅用于研究，不构成投资建议。

## 页面结构

| 文件 | 职责 |
| --- | --- |
| `QuantApp.jsx` | 模块外壳：四个 Tab（策略与回测 / 回测结果 / 今日信号 / 任务历史）、行情面板状态与预热、任务轮询 |
| `StrategyPanel.jsx` | 5 张策略卡 + 回测配置（区间、资金、仓位、成本、股票池、大盘过滤）+ 动态参数表单 + 最近回测 |
| `ParamForm.jsx` | 完全由后端 `ParamDef` 驱动：类型、默认值、min/max/step、说明 |
| `ResultPanel.jsx` | 指标卡（全样本 / IS / OOS）、净值 vs 基准 + 回撤、月度热力图、关键指标分段表、事件研究、交易明细 |
| `SignalsPanel.jsx` | 最新交易日扫描结果：候选、评分、建议止损、触发条件明细、策略级历史胜率 |
| `QuantParts.jsx` | 基础 UI（复用 ga.css 的样式变量与 .ga-* 类，不依赖 GA 的术语弹窗上下文） |
| `api.js` / `format.js` | 接口封装 / 比例与金额格式化（比例入参统一 0~1，红涨绿跌） |

## 数据流与性能

```
POST /backtests ──► 任务队列（2 线程）
                       │
                       ├─ 加载行情面板（首次约 8~9s，之后按快照缓存 30 分钟）
                       ├─ 策略求值：全市场 4606 只 × 491 日，纯内存滚动窗口
                       ├─ 回测撮合：以交易日为主循环
                       ├─ 绩效：ALL / IS(70%) / OOS(30%)
                       ├─ 事件研究：多持有期 × 月/大盘状态/板块/评分分档
                       └─ 批量落库（净值 491 行 + 交易 + 事件）
```

实测（本机，2024-11-06 ~ 2026-11-13，4606 只 / 491 日）：

| 操作 | 耗时 |
| --- | --- |
| 行情面板首次加载 | 8.2 ~ 9.3 s（1,545,815 行流式读取） |
| 单策略回测（含事件研究） | 0.4 ~ 1.7 s |
| 绩效 / 净值 / 交易 / 事件接口 | 6 / 8 / 8 / 22 ms |
| 每日选股扫描（5 策略） | 2.8 ~ 3.5 s；同快照同参数命中缓存 0.02 s |

设计要点：面板一次性加载并缓存，回测只做内存计算；信号结果不重复计算（回测与事件研究共用）；
列表与明细全部走主键/索引并分页。

## 交互约定

- 所有接口有加载态：提交后轮询任务进度并显示百分比与阶段，可取消；结果页在运行时显示进度条。
- 列表刷新沿用 GA 模块的 `useApi`（`reload()` 返回 Promise）+ `AsyncPanel` 三态（加载 / 空 / 错误），
  已有数据刷新时降透明度而不是清空。
- 交易笔数 < 30 时标红「统计不显著」；IS / OOS 必须同时看，避免只看全样本。
